# СКОЛ — сайт строительного бренда

Сайт СКОЛ: HTML/CSS/vanilla JavaScript, отдельные страницы услуг и портфолио. В репозитории также есть серверная CMS для публикаций, услуг, кейсов и обращений с сайта.

## Состав проекта

- index.html, styles.css, script.js — главная, фирменные стили и клиентская логика формы.
- services.html, services.js, services.css — каталог услуг, синхронизируемый с CMS при работающем сервере.
- demolition.html — подробная страница демонтажа и предварительный опросник.
- preparation.html, finishing.html, technical-floors.html — подробные страницы направлений.
- portfolio.html, portfolio.css, portfolio.js — портфолио, поиск, фильтры и переключение вида. Опубликованные CMS-кейсы заменяют демонстрационные карточки, когда они добавлены.
- publications.html, publication.html — публичная лента статей и страница материала, данные приходят из CMS API.
- admin.html, admin.css, admin.js — панель администратора.
- server.js — API, сессии, приём заявок и база SQLite.
- tests/cms.test.js — интеграционные проверки API.

## Возможности CMS

- Серверный вход администратора с HTTP-only cookie и ограничением попыток входа.
- Публикации, кейсы портфолио и услуги: создание, редактирование, черновик, публикация и архив.
- Заявки с публичной формы: сохранение в SQLite, поиск и смена статуса.
- Управление доступностью главной контактной формы и её сообщением подтверждения.
- Настройки компании, email, Telegram и региона.
- Публичный API отдаёт только опубликованные материалы; черновики не показываются посетителям.
- Фото и видео можно указывать по HTTPS URL или локальному пути. Загрузка медиафайлов через панель пока не реализована.

## Быстрый тест админ-панели на Windows

Для отдельного тестового стенда есть PowerShell-скрипты — вручную задавать пароль и переменные окружения не нужно.

1. Скачай или обнови репозиторий СКОЛ на компьютере.
2. В папке проекта нажми правой кнопкой мыши по пустому месту и открой PowerShell/Terminal.
3. Выполни:

    .\\start-demo.ps1

Если Windows блокирует запуск локального скрипта, только для этого окна PowerShell можно использовать:

    Set-ExecutionPolicy -Scope Process Bypass
    .\\start-demo.ps1

Скрипт проверит Node.js, при необходимости установит зависимости, создаст отдельную базу в `%LOCALAPPDATA%\\SKOL-Demo\\data`, сгенерирует временный пароль и откроет браузер. Логин и пароль будут показаны в окне PowerShell; пароль нигде в репозитории не сохраняется.

Адрес панели — локальный `http://127.0.0.1:<порт>/admin`. Порт выбирается автоматически в диапазоне 3210–3299. Тестовая база содержит демонстрационные заявки, статьи и кейсы с явной пометкой «ДЕМО». Изменения сохраняются между перезапусками, но не попадают в рабочую базу сайта.

Остановить сервер:

    .\\stop-demo.ps1

Тестовый режим намеренно запрещён при `NODE_ENV=production`; сервер слушает только `127.0.0.1`, а не внешний сетевой интерфейс. Это локальный стенд для проверки, а не публичная ссылка. Не используй его для настоящих заявок и не загружай реальные персональные данные.

## Локальный запуск на Windows

Нужен Node.js 20 или новее.

1. Откройте PowerShell в папке репозитория.
2. Установите зависимости:

    npm install

3. Задайте уникальные секреты. Не используйте примеры как реальные пароли и не коммитьте свои значения в Git:

    $env:ADMIN_USERNAME = "skol-admin"
    $env:ADMIN_PASSWORD = "Замените-на-сильный-уникальный-пароль"
    $env:SESSION_SECRET = [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
    $env:DATA_DIR = "$PWD\var"

Пароль должен содержать не менее 14 символов. SESSION_SECRET должен иметь не менее 32 символов.

4. Запустите сервер:

    npm start

5. Откройте http://localhost:3000/admin. Публичный сайт доступен на http://localhost:3000.

SQLite создаётся в DATA_DIR (по умолчанию var/skol.sqlite). Каталог данных блокируется от выдачи через статический сервер.

## Размещение на Vercel

Репозиторий подготовлен для статического сайта и отдельной serverless API-функции:
- `api/[...path].js` — API CMS для публикаций, услуг, портфолио, форм, заявок и настроек.
- `vercel.json` — адрес `/admin` ведёт на административную страницу.
- `DATABASE_URL` (или `POSTGRES_URL`) — строка подключения к постоянной PostgreSQL-базе. SQLite из локального сервера не используется функцией Vercel.
- `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SESSION_SECRET` — секреты входа и сессий; задаются только в Environment Variables Vercel.

### Настройка окружения

1. Подключите репозиторий `borzenkoofficial-lab/SKOL` к существующему проекту Vercel. Не создавайте второй проект, если этот репозиторий уже подключён к вашему production-домену.
2. Подключите PostgreSQL через Vercel Marketplace (например, Neon) либо используйте существующую совместимую PostgreSQL-базу. Возьмите pooled connection string от провайдера.
3. В Vercel → Project → Settings → Environment Variables добавьте:
   - `DATABASE_URL` — connection string PostgreSQL;
   - `ADMIN_USERNAME` — логин минимум из 3 символов;
   - `ADMIN_PASSWORD` — уникальный пароль минимум из 14 символов;
   - `SESSION_SECRET` — случайный секрет минимум из 32 символов.
4. Примените переменные к Production. Для Preview используйте отдельную тестовую базу либо не включайте административные функции в preview-среде.
5. Выполните новый deployment и проверьте `/api/health`, затем `/admin`. Первое API-обращение создаёт таблицы и начальные настройки/четыре услуги, если они ещё отсутствуют.

Не вставляйте значения секретов в GitHub, файлы проекта, сообщения или публичные логи. Для production не включайте тестовые демонстрационные заявки.

### Важные ограничения

- Код адаптации к PostgreSQL и Vercel подготовлен, но создание базы, добавление переменных окружения и production deployment требуют доступа к конкретному Vercel-проекту и к подключению провайдера базы.
- Проект Vercel и production-домен для СКОЛ пока не подтверждены. Не подключайте этот код к другому проекту по предположению: сначала определите проект, который действительно обслуживает сайт СКОЛ, затем отдельно настройте базу данных и секреты.
- При отсутствии `DATABASE_URL` `/api/health` вернёт `ok: false`; API не будет имитировать успешное подключение.
- Локальная Windows-демоверсия на `server.js` с SQLite остаётся отдельной и продолжает работать через `start-demo.ps1`. На Vercel используются PostgreSQL API и serverless-функция.
- Загрузка файлов с компьютера в CMS пока не реализована. Для обложек поддерживаются HTTPS URL или уже существующий локальный путь сайта.
